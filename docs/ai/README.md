## Commands

```bash
npm run ai:map
npm run ai:check
npm run ai:ask -- store outputs
npm run ai:ask -- channel OUTPUT
npm run ai:ask -- file src/frontend/components/output/Output.svelte
npm run ai:ask -- why src/frontend/components/output/layers/SlideContent.svelte:100
npm run ai:ask -- timers src/frontend/components/output
node --test scripts/ai-map/*.test.mjs
```

Queries are read-only, plain text, and show at most 12 references per section by default. Append `--all` for full results. Duplicate names prefer the desktop central store; `file#name` selects another store. A missing historical explanation remains explicit. Pure functions in [query.mjs](../../scripts/ai-map/query.mjs) accept a model and arguments; the filesystem CLI is separate, ready for a future MCP adapter.

## Confidence and scope

- `[verified]`: observed in the stated runtime experiment, with its environment and limits.
- `[code]`: established by current source or exact historical code evidence; not a runtime claim.
- `[guess]`: tentative interpretation, uncertain release-bullet matching, or unresolved motive. Unknown is not evidence of intent.

[code] JSON is split into table shards, named files/stores/channels/windows, and small array-part files. `loadModel()` hydrates the parts. Markdown indexes link the corresponding pages. The [manifest](generated/manifest.json) records compiler versions, source revision, fingerprints and limitations. Import/type graphs include tests under `src`; these are navigation evidence, not production runtime edges.

[code] Static analysis cannot prove arbitrary dynamic imports, helper mutations, runtime window branches, hardware availability, or exact IPC payloads without explicit types. Null timing values mean dynamic; they never mean zero. Component bindings preserve expressions and `bind:` directives, not evaluated values.

## Keeping the map current

1. Read the architecture guide and the relevant behavior findings. Query the affected file/store/channel before searching manually.
2. Regenerate after source changes. Do not hand-edit generated output.
3. Update subsystem/flow/history claims when their evidence changes. Add source anchors to `references.json`; registered claims require review after any change to their cited file.
4. Keep every code claim tied to a source reference and every historical motive tied to a quotation. Distinguish a line's most recent edit from its original addition.
5. Run `ai:check`. It compares all expected generated bytes, rejects extra files, validates Markdown local file/line/symbol links and plain source references, checks registered excerpts/symbols/file hashes, and requires history coverage when history exists.
6. Document suspected bugs without changing product code. Check the companion finding IDs first.

[code] External URLs are recorded but not fetched by `ai:check`; it does not validate remote link availability. Unregistered prose can be checked for a file and line's existence, but its meaning cannot be mechanically verified. `references.json` supplies stronger anchors for curated claims.
