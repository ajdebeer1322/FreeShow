# Live event recordings

[code] `npm run ai:trace -- list` lists the scenarios; `npm run ai:trace -- space-live` records one; `npm run ai:trace -- all` records the full catalogue. Build the ignored production fixture first with `node scripts/ai-map/runtime-build.mjs`. The runner starts Xvfb when DISPLAY is absent, uses the installed Playwright Electron API and unsets ELECTRON_RUN_AS_NODE. No GUI setup is needed.

[code] Each run creates an isolated FS_MOCK_STORE_PATH and removes it afterward. The fixture has four slides in two groups, shrinkToFit text, a looping video, an overlay and two enabled outputs. F4 adds a generated audio tone. Undo/redo scenarios prime history through a real text edit. Input scenarios use an injected input element; other contexts use app state and mounted components. No product source is changed. Ports 58510–58513 are reserved for this fixture; port 3000 is unused.

[code] The recorder hooks ipcMain.emit, existing/future ipcMain.handle handlers, and every output/main window webContents.send through electronApp.evaluate. It covers these Electron IPC APIs during the action interval, not worker MessagePorts, remote socket wire packets or traffic before instrumentation. Main-process stdout/stderr, renderer console and debug records are retained. DOM layer/opacity recording reuses config/testing/outputTimeline.ts; its per-window clock is aligned to the action wall clock (negative entries are the baseline before action). Debug recording is enabled through the actual shortcut after outputs exist and restored before later scenarios. Source revision, source fingerprint and recorder fingerprint are retained so ai:check rejects stale evidence.

[code] The JSON index lists each scenario, status and recording path. Each JSON contains before/after main state, observed central-store changes, IPC envelopes/payloads, console/errors/debug, each output DOM timeline and final output state. Only selected relevant central stores are subscribed; this is not a complete runtime store-write detector. JSON stores are sharded in the static map; trace payloads retain the fixture context so they can be replayed conceptually.

[code] Static comparison lists candidate event IDs, possible stores/IPC, observed stores/IPC and coverage gaps. Branches, callbacks and subscriptions make the static graph a may-call union rather than an execution order. An unobserved static effect is not a failure. A recorded no-op is a valid outcome; `verified` means the chosen action and resulting state were observed, not that all static paths were exercised. Physical audience displays, speaker audibility and external hardware are outside this fixture.
